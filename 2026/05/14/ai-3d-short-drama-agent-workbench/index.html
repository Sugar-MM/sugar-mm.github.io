AI 3D 短剧 Agent 工作台：从小说到视频片段的全流程创作系统

2026年5月14日

最近我做了一个个人 AI 项目：AI 3D 短剧 Agent 工作台。

它不是一个单点的文生图 Demo，也不是简单把一段 Prompt 扔给视频模型，而是一个面向 AI 短剧生产链路的 Web 全栈项目：用户输入小说章节或剧本文本，系统自动拆解角色、空间、道具和场次，生成世界资产、结构化分镜、Three.js 运镜预览，并接入图生视频任务，完成从文本到视频片段的闭环。

我希望它解决的是一个更具体的问题：AI 视频生成越来越强，但如果没有稳定的角色、场景、分镜和镜头结构，最后很容易变成“一次性生成”。这个项目尝试把短剧创作拆成可追踪、可确认、可恢复的工作流，让 AI 不只是生成结果，而是参与制作流程。

什么是 AI 3D 短剧 Agent 工作台？

AI 3D 短剧 Agent 工作台 是一个面向短剧创作的 AI Agent 平台。

它的核心链路可以概括为：

用户可以输入小说章节或短剧剧本，系统会根据目标创建一个 AgentRun，把任务拆成多个 AgentStep，并按顺序执行：

  1. 精简小说或转换剧本。
  2. 结构化解析角色、空间、道具、场次。
  3. 等待用户确认世界资产。
  4. 生成角色、空间、道具主图。
  5. 生成结构化分镜和分镜主视觉图。
  6. 生成 3D 运镜方案。
  7. 创建图生视频任务并同步视频结果。

和传统“一键生成视频”不同，这个项目更强调中间资产的可编辑和可复用。角色图、空间图、道具图、场次、分镜和视频任务都会落到 MySQL 中，后续可以继续编辑、重试和恢复。

核心特性

1. 从小说或剧本生成短剧世界

用户输入一段小说章节或剧本文本后，系统会先调用文本模型进行结构化解析，提取短剧制作所需的基础元素：

  • 故事设定
  • 人物关系
  • 角色
  • 空间
  • 道具
  • 场次
  • 空间关系
  • 视觉重点

这些内容不是临时字符串，而会沉淀成 ScriptAnalysis、WorldAsset、WorldScene 等数据结构。后续生成资产图、分镜图、3D 运镜和视频任务，都基于这套结构化结果继续推进。

2. 世界资产可确认、可复用

短剧生成最怕角色和场景不稳定，所以我没有让系统在解析后立刻一路自动生成到底，而是在“确认世界资产”这一步让 Agent 暂停。

用户可以先检查角色、空间、道具是否完整，再继续生成图片资产。这样可以避免模型理解偏差，也能减少不必要的生成成本。

资产层目前覆盖：

  • 角色资产
  • 空间资产
  • 道具资产
  • 资产提示词
  • 资产主图
  • 多候选图
  • 手动上传图片
  • 主图选择

当角色、空间和道具拥有稳定主图后，后续分镜图和视频生成就不再是孤立 Prompt，而是可以引用这些资产关系。

3. AgentRun / AgentStep 状态机

这个项目的核心不是“调一次模型”，而是手写了一个轻量工作流 Agent。

每次任务会创建一个 AgentRun，再根据任务类型生成一组 AgentStep。每一步都有自己的状态：

这样设计的好处是：

  • 用户可以看到任务执行到哪一步。
  • 长任务不用依赖一个超长 HTTP 请求。
  • 关键节点可以等待用户确认。
  • 失败步骤可以单独重试。
  • 已成功的中间产物不会丢失。
  • 历史任务可以恢复和继续查看。

这也是我认为它更像 Agent 项目的原因：模型负责理解和生成，系统负责规划、编排、状态流转、工具调用和结果持久化。

4. 分镜和 3D 运镜预览

在短剧场景里，只有文字分镜还不够。真正影响视频效果的是：

  • 人物站位
  • 空间关系
  • 镜头注视点
  • 焦段
  • 镜头运动
  • 分镜主视觉
  • 参考资产

所以项目里单独做了 3D 运镜预览器。它会根据场次地点、人物、道具、空间关系和分镜数据，生成基础站位与摄像机路径，让“镜头怎么走”变成可视化信息。

这一步目前不是为了做复杂 3D 建模，而是为了给后续视频模型提供更稳定的导演信息：视频模型不只拿到一句描述，还能拿到场次、镜头、角色和空间关系。

5. 图片生成、图生图和视频任务

项目当前接入了 Doubao Seedream 系列图片模型，支持：

  • 文生图
  • 一次生成 4 张候选图
  • 图生图二次编辑
  • 资产主图生成
  • 分镜主视觉生成
  • 生成历史保存
  • 图片下载代理
  • 缩略图生成

视频侧接入了 Seedance 图生视频任务。Agent 在生成分镜图后，可以根据主分镜图和视频提示词创建视频任务，并在后续同步视频结果。

技术架构详解

这个项目是一个 Next.js 全栈应用，前端、后端 API、Agent 编排、数据库、登录和部署都在同一个工程内完成。

前端与全栈框架

项目使用：

  • Next.js 16 App Router
  • React 19
  • TypeScript
  • Tailwind CSS
  • Three.js

页面层包括：

  • 首页产品入口
  • Agent 导演台
  • 剧本解析工作台
  • 世界资产编辑器
  • 3D 运镜预览器
  • 图片视频生成工作台
  • 登录页
  • 项目介绍页

Next.js App Router 负责页面组织，Route Handlers 负责服务端 API。图片生成、剧本解析、Agent 执行、视频任务、资产管理都通过后端接口完成，不把密钥和模型调用暴露到前端。

数据库层

项目使用 Prisma + MySQL。核心表包括：

  • User：用户和积分余额。
  • GenerationJob：图片生成、编辑等任务。
  • GenerationCandidate：一次生成的候选图。
  • Asset：图片、视频等资产。
  • AssetVersion：二次编辑版本关系。
  • CreditTransaction：积分流水。
  • ScriptAnalysis：剧本结构化解析结果。
  • WorldAsset：角色、空间、道具资产。
  • WorldScene：场次。
  • SceneStoryboard：分镜。
  • AgentRun：Agent 任务。
  • AgentStep：Agent 步骤。

这套数据模型的重点是把 AI 生成过程拆成可管理的业务对象。后续无论是做历史记录、失败重试、视频同步，还是做更复杂的项目工作区，都有清晰的数据基础。

AI Provider 层

项目没有把模型调用散落在页面里，而是做了 Provider 抽象：

  • Qwen：文本理解、小说精简、小说转剧本、剧本结构化解析、分镜生成。
  • Doubao Seedream：角色、空间、道具、分镜图等图片生成。
  • Doubao Seedance：图生视频任务。

这种抽象的好处是后续可以继续替换或增加模型，比如接入更多文本模型、视频模型或 3D Provider，而不需要重写业务流程。

Agent 编排层

Agent 编排层主要由三部分组成：

  1. Plan：根据任务类型生成执行计划。
  2. Executor：按步骤执行工具调用。
  3. State：用 MySQL 持久化 AgentRun 和 AgentStep。

当前支持的任务类型包括：

  • 小说转视频预视觉
  • 剧本转视频预视觉
  • 世界资产生成
  • 分镜生成
  • 视频生成

当前支持的核心步骤包括：

  • condense_novel
  • convert_novel_to_script
  • analyze_script
  • confirm_world_assets
  • generate_world_asset_images
  • generate_scene_storyboards
  • build_scene_director_plan
  • generate_video_clips
  • generate_final_report

我没有一开始就引入复杂 Agent 框架，而是先做“模板计划 + 工具执行 + 状态机”的方式。对这个项目来说，稳定、可追踪、可恢复，比让模型自由调用工具更重要。

登录、积分和安全

项目接入了 Google OAuth，用户登录后自动创建账号。

积分系统目前用于记录生成成本：

  • 文生图 4 张候选：扣 8 credits。
  • 二次编辑：扣 4 credits。
  • 资产主图、分镜图、视频任务也有独立成本常量。
  • 生成失败、配置错误或额度耗尽时不扣积分。

API Key 只存在服务端环境变量中。所有模型调用都走 Route Handlers，不会暴露到浏览器端。

Docker 与 CI/CD 部署

项目已经完成生产环境部署，线上地址是：https://devflow.aiyly.com/。

部署链路包括：

  • Docker 多阶段构建。
  • Next.js standalone 运行镜像。
  • 独立 migrator 镜像执行 Prisma db push。
  • GitLab CI/CD 自动构建、推送镜像和部署。
  • Docker Compose 管理服务。
  • Nginx 反向代理。
  • /uploads/ 静态资源目录独立挂载。
  • 生产环境变量通过 GitLab CI/CD File 类型变量注入。

这部分对我来说很重要，因为它让项目不是停留在本地 Demo，而是真正跑到了生产环境里。

如何使用？

访问：https://devflow.aiyly.com/

第一步：登录

使用 Google OAuth 登录。登录后系统会自动创建用户，并进入可操作的工作台。

第二步：选择创作路径

可以从 Agent 导演台开始，也可以手动进入分步工作台：

  • Agent 导演台：适合一键推进完整流程。
  • 剧本解析工作台：适合手动拆解小说或剧本。
  • 3D 运镜预览器：适合查看场次站位和镜头路径。
  • 图片视频生成工作台：适合独立生成图片、编辑图片和管理历史。

第三步：输入小说或剧本

输入一段小说章节或短剧剧本文本，填写目标后创建 AgentRun。

如果是小说，系统会先精简并转换为短剧剧本；如果已经是剧本，则直接进入结构化解析。

第四步：确认世界资产

系统解析出角色、空间和道具后，会进入等待确认状态。你可以检查资产是否完整，然后继续执行。

第五步：生成资产、分镜和视频任务

确认后，Agent 会继续生成资产主图、场次分镜、分镜主视觉、3D 运镜方案，并创建图生视频任务。

错误处理和任务恢复

AIGC 任务很容易遇到额度、网络、模型返回格式、图片地址过期等问题，所以这个项目从一开始就没有把流程设计成“一次请求跑到底”。

当前机制包括：

  • 每一步都有独立状态。
  • 失败时记录错误信息。
  • 失败步骤支持重试。
  • 已成功步骤不会被覆盖。
  • 关键节点可等待用户确认。
  • 历史任务可重新查看。
  • 生成图片会转存为本地资产，减少外部 URL 失效影响。
  • 列表和卡片优先读取缩略图，详情和下载再读取原图。

这种设计虽然比简单 Demo 更复杂，但它更接近真实生产工具。

适用场景

1. AI 短剧创作者

把小说、爽文、短剧脚本快速拆成角色、场景、分镜和视频片段，减少从文本到视觉方案的前期成本。

2. 编导和分镜策划

用它快速得到场次拆解、镜头运动、主视觉图和 3D 运镜草案，再人工精修。

3. AIGC 产品原型验证

这个项目可以作为 AIGC 工作流产品的原型，验证“用户确认 + 多模型协作 + 资产复用 + 状态机”的产品体验。

4. 前端 / 全栈 / AI 应用开发展示

项目覆盖 Next.js、Prisma、MySQL、OAuth、Docker、CI/CD、Three.js、AI Provider、Agent 状态机和生产部署，比较适合作为 AI 应用全栈能力展示。

与传统方式的对比

维度 传统 AI 视频生成 AI 3D 短剧 Agent 工作台
输入方式 一段 Prompt 小说章节或完整剧本
过程控制 黑盒生成 分步骤执行，可确认、可重试
角色一致性 依赖 Prompt 描述 角色资产主图可复用
场景管理 临时描述 空间、道具、场次结构化保存
分镜能力 通常缺失 自动生成结构化分镜
运镜信息 文本描述为主 Three.js 可视化预览
任务恢复 失败后通常重来 AgentStep 可单步重试
工程化 多为 Demo Docker + GitLab CI/CD + Nginx 生产部署

未来展望

接下来我希望继续完善几个方向：

  • 更完整的视频任务队列和状态同步。
  • 角色语音包、对白配音和字幕生成。
  • 多视频片段排序和成片导出。
  • 更强的角色一致性策略。
  • 更细的镜头语言控制。
  • 3D 资产生成或第三方 3D 工具接入。
  • 项目式工作区，让一个短剧项目管理多集、多场次、多资产。
  • 团队协作和分享能力。

最终目标不是做一个“生成按钮”，而是做一个 AI 短剧制作工作台：让小说、剧本、角色、空间、分镜、镜头、视频和声音都能被统一组织起来。
